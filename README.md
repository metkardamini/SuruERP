# Suru ERP

Manufacturing ERP for Suru Industries (precision job shop, Malegaon MIDC, Sinnar, Nashik), built by Daivo Solutions.

Phase 2 moves the ERP from browser `localStorage` to a shared **Supabase** backend. Go-live: **1 Dec 2026**.

## Repository layout

| Path | What it holds |
| --- | --- |
| `supabase/migrations/` | Every database change, in order. Applied to the live project; never edit an applied file, add a new one. |
| `supabase/tests/` | SQL checks run after each database change. They roll back everything they touch. |
| `supabase/functions/` | Edge Functions (logins, AI PO parsing). Added from 17 Nov. |
| `web/` | The ERP itself (`index.html`), deployed by Netlify. Currently the 28 Sep baseline (BUILD_VERSION v35, localStorage). |
| `tests/` | Playwright and data checks (E2E scenarios, test cases, normCode parity). |

## Database at a glance

- **27 tables**: 23 ERP + 4 HRMS shared (`employees`, `attendance`, `leave_records`, `designation_role_map`).
- **Product Code** is the unique key: each product-bearing table has `code_norm`, generated by `norm_code()`, which matches the ERP's `normCode()` exactly (checked on 573 codes from build v35, 0 differences). `products.code_norm` is unique.
- **IDs** come from `next_id('<PREFIX>')` in the ERP's existing formats (PT-0001, CUS-001, SHP-1043 ...). Counters live in `id_counters` and are not directly readable.
- **Optimistic locking**: editable tables carry `version`. Send the version you read; a stale save fails with SQLSTATE `40001` and the user is asked to reload.
- **Security**: row-level security is on for every table. Logged-out visitors get nothing. Access follows the ERP's Roles & Permissions matrix (`role_permissions`) through `can(area)`; Admin always passes. Supplier bank details are Admin/Purchase only. `activity_log` is append-only.
- **Files** (drawings, photos, logos, dispatch documents) go to the private `erp-files` storage bucket; tables hold only the path.
- **HRMS**: adding an employee whose designation is mapped in `designation_role_map` auto-creates the ERP `staff` row.

## Working rules

- One versioned ERP build per day: `Suru_ERP_[Date]_v[N]`, zero console errors, full Playwright regression before delivery.
- Every database change is a new migration file here, applied to Supabase the same day.
- Demo data only until go-live (Demo Product 1-3, Demo Customer 1-2, Demo Supplier 1-2, Demo Staff 1-4, Demo PO 1-2). Real data is entered after go-live.
- Staff PINs stay 4 digits (decision 16 Nov); the ERP pads them internally to meet Supabase's 6-character password minimum.
